Scope and ANTUSDT facts

01Read this first

This is the procedure for listing one new market that is executed as A-Book: users trade on NeoDAX, the market maker hedges on Binance. ANTUSDT-PERP is the worked example, and every value was read from Binance on 2026-11-20.

What "A-Book" means for a new market

A new A-Book market is born A-Book. There is no book switch, no marketctl book-switch, and it is never added to a Finex shard. Execution goes through the MM connector to Binance, and quote mirrors Binance market data. The market is created FROZEN and opened only after every check passes.

  • Mark price, order book, trades, klines and ticker all come from the same Binance symbol. The A-Book mark source weight is Binance 1.0 only.
  • Margin mode is isolated only.
  • One market at a time: validate while FROZEN, open it, observe, then the next one.

Gates and owners

02Before release day

Nothing below changes production. Each gate has an owner, and a failed gate stops the release.

Gates

  • STOPBinance status is not TRADING, or contract type is not as expected.
  • STOPSeed values differ from the release-day snapshot (tick, step, min, max, notional, price band, funding, interest, liquidation fee).
  • STOPNo leverage bracket, tiers not strictly increasing, or max_net_notional above the tier-1 notional cap.
  • STOPThe Binance execution account has no trading permission, no isolated setting, or not enough margin for ANTUSDT.
  • STOPThe A-Book House account is missing (see 02-3).
  • RECORDRaw JSON, extracted table, SHA-256 and reviewer are attached to the release ticket.

Create the market through the Admin API, not SQL alone

The Admin API writes the row through the Raft state machine and publishes CommandMarketSync, so every component learns about the market. Direct SQL only inserts the row. The 2026-10-27 ARB incident came from stopping at SQL.

  1. Create the base asset if it is missing.POST /perpetual/asset with symbol ANT, or the idempotent SQL below.
  2. Create the market.POST /perpetual/market with the field values above. Later edits use PUT /perpetual/market.
  3. Confirm the state before anything else.GET /perpetual/market/ANTUSDT-PERP/a-book/status must show A_BOOK, routing ACTIVE and operational state FROZEN.
  4. Confirm the connector saw it.The mm_connector log shows A-Book market sync processed with added=1 for this market. Confirm Finex does not hold it.
  5. Write the risk tiers.SQL, executed by DevOps. See 03-3.

Risk tiers from the leverage bracket

Rules: notionalCap becomes max_position_qty, initialLeverage becomes max_leverage, initial_margin_rate = 1 / initialLeverage, and maintenance_margin_rate = maintMarginRatio × 2 for tier 2 and above. Tier 1 is used as returned. Doubling the rate makes our liquidation fire before Binance liquidates the hedge.

The script below applies these rules. It was run against the published XAUUSDT bracket and reproduced all 10 rows of the published seed.

Script: bracket_to_sql.py
#!/usr/bin/env python3
"""Turn a Binance leverageBracket response into perps_market_risk_tiers SQL.

usage: bracket_to_sql.py <leverageBracket.json> <INTERNAL_SYMBOL, e.g. ANTUSDT-PERP>
Rules: notionalCap -> max_position_qty, initialLeverage -> max_leverage,
initial_margin_rate = 1/initialLeverage (8 dp), maintenance_margin_rate =
maintMarginRatio x 2 for tier 2 and above, tier 1 as returned.
"""
import json, sys
from decimal import Decimal, ROUND_HALF_UP

def num(x):
    s = format(Decimal(str(x)).normalize(), 'f')
    return s

def main(path, symbol):
    data = json.load(open(path))
    entry = data[0] if isinstance(data, list) else data
    brackets = sorted(entry["brackets"], key=lambda b: b["bracket"])
    prev = Decimal(0)
    rows = []
    for b in brackets:
        cap = Decimal(str(b["notionalCap"]))
        assert cap > prev, "tiers must strictly increase by notional cap"
        prev = cap
        lev = Decimal(str(b["initialLeverage"]))
        imr = (Decimal(1) / lev).quantize(Decimal("0.00000001"), ROUND_HALF_UP)
        mmr = Decimal(str(b["maintMarginRatio"]))
        if b["bracket"] > 1:
            mmr *= 2
        rows.append("    ('%s', %d, %s, %s, %s, %s, 1, NOW(), NOW())" % (
            symbol, b["bracket"], num(cap), num(lev), num(imr), num(mmr)))
    print("INSERT INTO portfolio_manager_perp.perps_market_risk_tiers (\n"
          "    symbol, tier_index, max_position_qty, max_leverage,\n"
          "    initial_margin_rate, maintenance_margin_rate,\n"
          "    config_version, created_at, updated_at\n)\nVALUES")
    print(",\n".join(rows))
    print("ON CONFLICT (symbol, tier_index) DO UPDATE SET\n"
          "    max_position_qty = EXCLUDED.max_position_qty,\n"
          "    max_leverage = EXCLUDED.max_leverage,\n"
          "    initial_margin_rate = EXCLUDED.initial_margin_rate,\n"
          "    maintenance_margin_rate = EXCLUDED.maintenance_margin_rate,\n"
          "    config_version = EXCLUDED.config_version,\n"
          "    updated_at = NOW();")

if __name__ == "__main__":
    main(sys.argv[1], sys.argv[2])
python3 bracket_to_sql.py leverageBracket.json ANTUSDT-PERP > ant_risk_tiers.sql

Review the generated rows against the raw response, then DevOps runs the file. The tier-1 values also fill the three __TIER1_*__ placeholders above. PM Perp re-reads market definitions every minute, so allow about 70 seconds before the next check.

Easy to miss

perp_trigger.yaml is not in the older runbook. perp_trigger subscribes to each market's order-update and trade topics once, at start (perp_trigger/service.go), so without this entry trigger orders (stop and take-profit) for ANT would not complete on cancel.

Displayed volume multiplier (optional)

The mirrored 24 h volume is scaled so that the displayed number is between 0.5 M and 5 M USDT, as for the other A-Book markets. ANT trades about 3.22 B USDT in 24 hours, so a multiplier of 0.0015 shows about 4.8 M. Existing precedents: GOOGL 0.005 (about 4.2 M), XAU 0.002 (about 4.7 M). The key is cosmetic and harmless if unused. The final number is a product decision.

Quote capacity

Each new mirrored market adds a REST depth bootstrap, a diff stream, a local book, klines, trades and ticker. Quote shares one Binance REST budget (rest_weight_per_minute: 600). One more market is small, but watch quote CPU and the SAFE_MODE state during the first hour after the restart, because a throttled quote drops mark samples for every market.

Restart list

quote · ledger · perp_trigger · trading-api · PM Perp (rolling). This is the full list. A restart that is skipped shows up later as an empty order book or lost trigger orders, not as an error.

FROZEN acceptance

  • The A-Book status shows A_BOOK, ACTIVE, FROZEN and route_version = 1.
  • The market row equals the release-day snapshot, field by field.
  • The risk tiers read back through ListPerpsMarketRiskTiers match the generated rows.
  • Order book mirror: about 50 levels per side and a spread of about one tick.
  • Mark, index and funding rate are non-zero and moving, and the mark source weight is Binance only.
  • Quote is not in SAFE_MODE. Klines and ticker are flowing. The 24 h volume shows the scaled value.
  • The MM connector is connected and heartbeating, the risk snapshot is fresh, and the House account exists.
  • Alerts are loaded and reach on-call.
FROZEN to OPEN, then canary

06Open the market

Opening runs the readiness gate and closes the connector circuit. An HTTP 200 is not enough: the response body must have code == 0.

Open

GET  /perpetual/market/ANTUSDT-PERP/a-book/status      # read route_version

POST /perpetual/market/ANTUSDT-PERP/a-book/state
{
  "operation_id": "<new UUID>",
  "state": "OPEN",
  "reason": "new A-Book market rollout ANTUSDT <ticket>",
  "expected_route_version": 1
}

If the connector snapshot is stale the gate refuses. Wait about a minute and retry. If a validation error mentions precision or a required field, fix the row, wait about 70 seconds for PM Perp to reload, and try again.

Canary

  1. Resting order.A post-only limit order at a safe distance from the mid. Check it rests, then cancel it and check there is no residue.
  2. Fill.The A-Book MM is RFQ-style: only orders that cross immediately fill. Use a small MARKET order, then close the position.
  3. Check.Trade history, position and PnL are correct and the fee is 2 bps maker / 5 bps taker. The Binance hedge appears on the main account. No reconciliation diff.

Requests with invalid precision, below the minimum notional, above the maximum leverage or tier, or above max_net_notional must all be rejected.

Observe

Watch the A-Book dashboards, reconciliation diffs and the alerts above before the next listing. For a new equity-style contract, ask the MM team how the hedge and the price behave outside US market hours. TODO: this was not checked here.

Freeze first

07Rollback

On any failure, freeze, keep the evidence, and repair along the A-Book path. Rollback never changes execution ownership.

Steps

  1. FROZEN immediately.POST /perpetual/market/ANTUSDT-PERP/a-book/state with state FROZEN. Never book-switch to B-Book.
  2. Keep evidence.Operation id, route version, connector offsets, orders and fills, the Binance account snapshot, reconciliation diff, market data sequence and the alert timeline.
  3. Handle exposure.While any user, House or Binance position exists, stay FROZEN and repair through the A-Book cancel-all, reconcile and reconcile-order operations.
  4. Orphaned margin locks.Orders that locked margin but never produced an order row are reaped daily at 02:00 UTC. For an immediate release use perpctl lock-reconciler with --dry-run first.
  5. Remove config only from zero.Only with zero positions, orders, triggers, unsettled funding and Binance exposure may the market be disabled and removed from the subscriptions.

If Binance changes filters, funding or brackets during the rollout, freeze the market, take a new snapshot and open again only after the difference is reviewed.
