02运营能做什么

划转有两种，每一笔都由一个人提案、另一个人审批。运营只选资产、填金额和原因，其他内容都是固定的。

  • 入金（Funding）：托管合约 → 中转地址 → Binance 充值地址，链上两段。
  • 扫回（Sweep）：中转地址 → 托管合约，链上一段。

运营不能指定的内容

请求里不带地址、网络和密钥。目标地址、所在的链、单笔最小和最大金额、每日限额，都来自 Cage 里固定的一份配置（profile）。后管只负责展示。

六种操作

  • 提案入金
  • 提案扫回
  • 审批别人的提案
  • 拒绝别人的提案
  • 撤销自己的提案
  • 放弃一笔卡住、且当前这一段还没有发出的操作
代码依据路由：admin/router/platform_finance.go。处理函数：admin/api/platform_finance/binance_treasury.go。接口类型的注释写明请求不带地址、网络和密钥。
不属于本流程neodax PR #1775 做的是用户提现的风控审核，和资金划转无关。
待确认 · Q1提案人和审批人按用户区分，不按角色区分。见第 12 节。

04状态与可用操作

一笔操作在 Admin 里有十种状态，只有第一种接受人的决定。审批通过之后全部自动进行，直到完成、失败或卡住。

approval_pending ─ 审批 ─▶ approved ─ 派发 ─▶ executing ─▶ completed
  ├─ 拒绝 ─▶ rejected
  ├─ 撤销 ─▶ cancelled
  └─ 24 小时 ─▶ expired

approved      ─▶ failed_retryable ─ 自动重试 ─▶ executing
approved      ─▶ failed_terminal   # Cage 拒绝
executing     ─▶ manual_review     # Cage 报告卡住
manual_review ─ 放弃 ─▶ failed_terminal
manual_review ─ 这一段有了进展 ─▶ executing
executing     ─▶ failed_terminal   # 某一段彻底失败

接口里的状态值是小写字符串，例如 approval_pending。

代码依据状态常量：admin/model/platform_finance.go:10-19。根据 Cage 证据推进状态：admin/service/platform_finance/binance_treasury.go 的 applyEvidenceTransition。
有两个状态字段页面显示哪些按钮，由上面的 Admin 状态决定。Cage 另有一套更细的状态（LEG1_IN_PROGRESS 等），作为补充信息展示。
Admin 状态含义怎样进入运营可做的操作页面显示什么
approval_pending等待第二个人决定创建提案其他人：审批、拒绝。提案人：撤销距离 24 小时过期还剩多久
approved已审批，等待发给 Cage审批通过无正常只持续约 2 秒
executingCage 已受理，正在划转Cage 受理，或某一段已发出、已确认无各段的交易哈希和确认数
failed_retryable发给 Cage 失败，之后可能成功派发时超时或网络错误无已尝试次数、最近错误、下次重试时间
manual_reviewCage 报告这笔操作卡住了收到 OPERATION_STALLED 证据放弃，前提是当前这一段从未发出卡住的原因，资金是否在中转地址
completed所有段都已在链上最终确认收到 OPERATION_COMPLETED 证据无最终交易，金额计入净流量
failed_terminal不会再继续Cage 拒绝、某一段彻底失败，或被放弃无。仍然需要的话重新提案错误码和错误信息
rejected被第二个人拒绝拒绝无谁拒绝的，原因是什么
cancelled提案人自己撤回撤销无—
expired24 小时内没人决定后台任务无—

提交时后端检查什么

  1. 功能开关入金和扫回各有一个开关。开关关闭时请求失败。
  2. 必填项资产和原因不能为空，金额必须大于 0。
  3. Cage 配置配置必须已启用，执行必须开启，资产必须在配置里。
  4. 金额范围在该资产的最小值和最大值之间。
  5. 仅扫回：可扫回余额不超过中转地址的可扫回余额（Cage 已知余额时才检查）。
  6. 幂等键必填。同一个键加同样的内容，返回已有的提案。同一个键加不同的内容，报冲突。

提案时不检查每日限额。它在审批时预检，最终由 Cage 控制。

请求POST /fundings 或 POST /sweeps，字段为 asset、amount（十进制字符串）、reason，可选 risk_context。幂等键放在 Idempotency-Key 请求头或 idempotency_key 字段里。
提案时固定下来的内容配置 ID、配置指纹、链 ID 和网络随提案一起保存。之后配置如果变了，审批会被拒绝。
待确认 · Q3、Q14幂等键由后管页面生成。这一步不检查金额的小数位数（后端缺口）。

06审批、拒绝、撤销

三者都只对 approval_pending 状态的操作有效，按钮放在操作详情里。

审批

  • 审批人不是提案人。
  • 这种划转的功能开关仍然开着。
  • Cage 配置仍然启用，配置 ID 和指纹与提案时保存的一致。
  • 这种划转、这个资产今天已审批的金额，加上本笔金额，不超过每日限额。

审批记录、状态变更和"发给 Cage"的消息写在同一个数据库事务里。审批的原因是选填的。

拒绝

必须填原因。提案人不能拒绝自己的提案，只能撤销。

撤销

只有提案人可以撤销。接口没有原因字段。

过期

没人处理的提案在创建 24 小时后变成 expired。这是后台任务做的，所以到期后几秒内状态会变。

这里的每日限额只是预检两个审批人同时操作时，可能都通过这项检查。真正的限额由 Cage 在加锁的情况下控制。后到的那一笔会被 Cage 拒绝，最终是 failed_terminal，错误码 DAILY_LIMIT_EXCEEDED。不会多划出资金。
代码依据ApproveBinanceTreasury，然后是 approveOperation（service.go:87-130，outbox 记录在第 124 行）。
待确认 · Q4、Q5、Q6页面上审批要不要强制填原因，撤销要不要原因，要不要通知相关人。

07跟踪执行

审批通过之后不需要任何人点击。运营在操作详情里看进度。

  1. 派发，约 2 秒内Admin 的后台任务把已审批的操作发给 Cage，并用双方共享的密钥签名。同一时间只有一个 Admin 副本在做这件事。
  2. Cage 受理或拒绝Cage 先验证签名，再检查配置、金额范围、每日限额；扫回还要检查可扫回余额；入金还要检查托管提现熔断器没有打开。被拒绝的操作变成 failed_terminal。
  3. 入金第 1 段：托管 → 中转地址Cage 发起一笔托管提现到中转地址，并等它最终确认。
  4. 入金第 2 段：中转地址 → Binance中转地址把代币转到 Binance 充值地址。交易迟迟没有打包时，Cage 会提高手续费，直到配置的上限。
  5. 扫回：只有一段中转地址把代币转回托管。
  6. 完成最后一段最终确认后，金额计入净流量，只计一次。

08人工复核

Cage 报告操作卡住时，状态变成 manual_review。这是审批之后唯一允许人工操作的状态。

什么情况会卡住

  • 某一段因为同一类错误持续失败，超过了配置的时间（示例配置是 30 分钟）。
  • 中转地址发出的交易被打包但执行失败，次数超过了允许值（示例配置是 2 次）。

卡住的操作 Cage 仍然会继续尝试。如果这一段之后有了进展，操作会自己回到 executing。

放弃之后操作变成 failed_terminal。如果没有任何一段已经最终确认，这笔金额会从当日已用额度里退回。

09配置与健康状态

页面顶部要让运营在提案之前就知道，现在发起划转能不能成功。

每个资产显示

  • 单笔最小和最大金额。
  • 每日限额和今日已用，入金和扫回分开。
  • 中转地址上的余额，以及其中可以扫回的部分。
  • 在途金额：第 1 段已确认、第 2 段还没确认的入金。
  • 净入金：已确认转出减去已确认扫回。它记录的是经过这个流程的资金，不是 Binance 账户余额，可以是负数。

页面必须显示的提醒

  • 阻断Cage 的执行被禁用，或配置没有启用。提案会被拒绝。
  • 阻断证据读取已停止。在工程师处理之前，页面上的状态可能不是最新的。要显示停止的原因和卡住的那条证据。
  • 警告中转地址的 Gas 状态是 LOW 或 BELOW_RESERVE。从它发出的转账可能发不出去。
  • 警告余额过期或未知。显示的可扫回金额可能不准。
  • 警告证据延迟持续大于 0。
Gas 状态取值为 OK、LOW、BELOW_RESERVE、UNKNOWN。给中转地址充 Gas 不在这个流程里。
证据读取停止当一条证据指向 Admin 没有派发过的操作，或和已审批的内容对不上时，Admin 会停止读取，不会自己跳过。GET /ingestion 返回 halted、halt_reason（unknown_operation、evidence_drift、apply_error）、halted_event_id 和 lag。

10接口一览

所有路径都在 admin-service 的 /platform-finance/binance-treasury 下，需要登录的后管账号和 Casbin 授权。PR #1868 的迁移把这 11 个接口都授权给了角色 1。

返回格式和其他后管接口一样：成功时 code 为 0；失败时 message 是第 11 节里的文字。

字段名的大小写操作本身的字段是首字母大写的（ID、State、OperationType、ProposerUsername、CreatedAt），因为 Go 结构体没有写 JSON 标签。嵌套的 details、execution、approvals、evidence、cage 是下划线小写。dashboard 现有的 PlatformFinanceOperation 类型已经是这样写的。
不对外admin-service 只能在内部网络访问，这些接口都不暴露到公网。

#主题后端现在的行为本文对页面的假设
Q1角色11 个接口都授权给了角色 1。提案人和审批人必须是不同用户，但可以是同一个角色。保持一个角色。如果要求提案和审批是不同角色，需要改 Casbin 规则。
Q2页面放在哪PR 没有新增菜单。在 Platform Finance 页面里加一个标签页。
Q3幂等键必填。同一个键加同样内容，返回已有的提案。每次打开弹窗由页面生成一个键，同一次提交重试时复用。
Q4审批的原因审批选填，拒绝和放弃必填。页面上也是选填。
Q5撤销只有提案人可以，没有原因字段。一个普通的确认框，不填原因。
Q6通知没有。新提案、过期、卡住都不会通知任何人。第一版不做通知，审批人自己看列表。
Q7列表条数最新 500 条，不分页，可按类型、状态、资产筛选。第一版够用。
Q8刷新后端不推送，页面只能轮询。操作进行中时每 5 秒刷新一次。
Q9谁可以放弃有这个接口权限的任何用户，包括提案人和审批人。一个人就够。保持现状，必须填原因，用红色确认按钮。
Q10留在中转地址的资金留在原地。取回要走普通的扫回。显示提示，并提供"提案扫回"按钮，预填资产和金额。
Q11手动重试派发会自动重试，等待时间翻倍，最长 5 分钟。没有"立即重试"的接口。不做手动重试，只显示下次重试时间。
Q12"今日已用"有两个数字：Cage 已受理的金额（在 profile 里），和 Admin 审批预检用的已审批金额。两者可能短暂不一致。显示 Cage 的数字，因为限额由 Cage 控制。
Q13地址和交易地址和哈希以文本返回。完整显示，带复制按钮和区块浏览器链接。每个网络的浏览器地址需要提供。
Q14金额小数位数 后端缺口Admin 接受最多 20 位小数。小数位数超过资产精度时，Cage 在审批之后才拒绝。profile 不返回资产的小数位数。在 profile 返回里加 decimals，并在提案时检查。在这之前，位数超了的金额要到审批之后才失败。
Q15熔断器和读取停止的可见性 后端缺口托管提现熔断器打开时，入金会被 Cage 拒绝，但 profile 不返回熔断器状态。证据读取停止只能通过 GET /ingestion 和一个监控指标看到。在 profile 里加熔断器状态，页面据此把提案按钮置灰。另外要定证据读取停止时通知谁。

13上线前还缺什么

后端逻辑已经具备，但运营现在还用不了。

  • 未完成PR #1868 还没有合并，评审状态是要求修改。还有一条评审意见没关闭，评审人把它定为阻塞项：有一列是通过修改已有的迁移文件加上的，这个迁移在某些环境里可能已经执行过。
  • 未完成本文描述的后管页面还没有开发。
  • 配置Admin 的两个功能开关默认关闭，Cage 还有自己的配置开关和执行开关。
  • 配置运维需要准备双方共享的签名密钥、中转地址及其密钥，以及 Cage 配置里的资产列表。示例配置里资产列表是空的。
  • 运维中转地址上要有 Gas。给它充 Gas 不在这个流程里。
